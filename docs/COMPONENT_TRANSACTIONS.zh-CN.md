# 组件安装事务

[English](COMPONENT_TRANSACTIONS.md) | 简体中文

组件平台防护普通应用崩溃、互相冲突的宿主操作及误删所有权范围之外的文件。它不试图阻止同一用户的其他进程篡改私有 JSON。包验证与 Host API 权限边界仍然有效。

## 所有权和准入

生命周期协调器在破坏性操作之前停止接收新工作，排空 Host 调用，等待组件进程和页面停止。进程树停止失败仍会阻止卸载和正常退出。事务服务按组件串行化操作及恢复；全局恢复等待所有活动操作。

每个获准操作有两个文件：

```text
components/.transactions/<component-id>/
  receipt.json   不可变操作、路径、原始身份及用户选择
  state.json     当前阶段、清理进度和最近错误
```

两个文件先在私有 `.admit-<component-id>-<operation-id>` 中准备，再发布整个目录。准入前不得重命名运行库或执行事务清理。调用方仅在准入成功后转交准备文件所有权。

大文件清单只存储在收据中一次。状态用操作 ID 和一个内容摘要绑定收据。状态写入使用同目录且已同步的临时文件，替换当前文件前不先 unlink；不生成历史状态文件或哈希链。这些保证覆盖进程崩溃；Node Windows API 无法对目录 fsync，因此不保证每次断电都能恢复。

格式为 schema version 3，不提供旧格式读取或迁移。未知或无效活动记录会保留并阻止所属组件。

## 恢复决策

| 安装阶段 | 恢复方式 |
| --- | --- |
| `prepared` | 根据身份及实际位置恢复旧运行库 |
| `published` | 移除新运行库并恢复旧运行库 |
| `host-committing` | 重复幂等 Host 提交并继续向前 |
| `cleanup-pending` | 保留新运行库并完成清理 |
| `done` | 只回收元数据，不重放启用状态或设置 |

仅向前恢复的决定先于 Host 设置迁移写入。正常安装与启动恢复使用同一 Host 提交函数；启用状态在写入 `done` 前完成。

卸载使用 `prepared`、`quarantined`、`cleanup-pending` 和 `done`。即使后续状态写入中断，也能识别已完成的隔离重命名。隔离后继续完成卸载，不假装可以回滚已部分清理的用户数据。显式数据清理先记录 `executing`，完成后记录 `applied`；处理器必须幂等。错误通过 `lastError` 保留恢复阶段。

## 文件清理

运行库及事务所有的准备目录按原始收据校验。首次尝试检查整棵树、保存 `executing`，然后删除。重试只接受原树的匹配子集，缺失项视为已删。新增文件、内容变化、身份不符、目录联接、链接和越界路径均停止清理。文件逐个删除，目录只在为空时删除。不创建 intent、proof 或 verified 旁路文件。

准入前，失败的解包和复制阶段属于可丢弃临时目录。后台任务服务对这些路径保存精简根身份收据，避免任务历史过大。只接受配置的临时/安装根目录下精确的 package-stage、package-snapshot、install-stage 命名，不接受已安装运行库、组件用户数据或任意目录。遍历仍拒绝链接并验证节点身份。后台任务准入必须持久化后才能开始清理。

## 完成后的元数据

`done` 后，整个日志目录移到 `.retired-<component-id>-<operation-id>`，再删除已知 JSON/临时文件。失败只记录应用警告，不把成功安装或卸载变为失败。全局恢复会重试整理，不跟随退休收据中的业务路径，保留未知文件。不设 GC 标记或独立 GC 事务；按组件过滤的恢复绝不清扫其他组件准入目录。

## 验证范围

上游事务测试覆盖发布/回滚中断、真实子进程退出、Host 提交失败、部分删除、用户数据清理重试、所有权错误、状态替换失败、元数据清理失败、大收据和操作/恢复并发。上游组件发布门禁包含这些测试，生命周期、退出、Host API 及 Windows Job Object 测试覆盖外围边界。

本公开仓库未提供这些上游套件的 npm 命令。可用命令以 `package.json` 及根 README 为准；本次源码更新没有运行本地验证。
